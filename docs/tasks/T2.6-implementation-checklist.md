## Conventions

- **Coordinate frames:** `OpenCV` (right-handed, +Y down, +Z forward) → `Unity` (left-handed, +Y up, +Z forward). All conversions go through one utility class `CoordinateConverter` (THEORY.md §6.3). Never duplicate the conversion. **[F05]** The basis change `F = diag(1, -1, 1)` applies to poses AND to geometry in the same step: `R' = F R F`, `t' = F t`, and for scalar-first quaternions `q' = (w, -x, y, -z)` when both the local and camera coordinates change basis. Applying it to the pose but not to the node coordinates (or the reverse) mirrors the wireframe.
- **Units:** metres, throughout. UNV is metres. Camera intrinsics in pixels.
- **Time [F05]:** nanoseconds, but every timestamp names its clock. Three clocks exist and must never be compared without an explicit mapping: the SDK camera-frame clock, the Unity/host clock that stamps head-pose samples, and the Python service's own monotonic clock. `XREALPlugin.TryGetRGBCameraFrame(ref ulong)` returns the SDK camera-frame time; whether it shares an epoch with the head-pose clock is **unverified** and must be measured (Phase 5.1) before any composition uses both. The service echoes the uplink `timestamp_ns` and `clock_id` unchanged in every response; it never substitutes its own receive time for the frame time.
- **Transform naming [F05]:** every transform is written `T_destination_from_source` (maps source-frame coordinates into the destination frame). Compose right-to-left by matching inner names: `T_world_from_structure = T_world_from_head * T_head_from_camera * T_camera_from_structure`. Names such as `worldToStructure` are banned because they invert readers' expectation of what the matrix does.
- **Threading:** WebSocket I/O on a background task; pose results posted to the Unity main thread via `XREALMainThreadDispatcher.PerformActionInUpdate()` (already in the SDK).

## Phase 1 — EyeLab Service (Python WebSocket) (~3–4 days)

**Goal:** standalone Python service running on Windows that consumes JPEG-encoded frames over WebSocket and replies with ArUco-derived poses, reusing all existing webcam-pipeline logic.

### 1.1 Dependencies

- [ ] In `python/requirements.txt`, add `websockets>=12` (server lib) and `python-msgpack` is **not** needed (we use raw binary + JSON).
- [ ] `python -m venv venv && venv\Scripts\activate && pip install -r requirements.txt`.

### 1.2 Frame protocol (`python/frame_protocol.py`) **[F08]**

Write the schema and golden fixtures first (`python/tests/fixtures/protocol/`), then both endpoints against them. One executable definition; the C# side reads the same fixtures.

- [ ] Uplink frame = one WebSocket *binary* message: a **20-byte** header followed by the JPEG payload. Python `struct` format `<4sB3xIQ` (little-endian, no padding): `magic[4] = b'ELAB'`, `version` (uint8, = 1), 3 reserved zero bytes, `seq` (uint32), `timestamp_ns` (uint64). 4+1+3+4+8 = 20 (the earlier "16 bytes" was an arithmetic error).
  - `seq` wraps modulo 2^32; compare with serial-number arithmetic, never plain `<`.
  - Reject, with a typed error and without crashing: wrong magic or version, non-zero reserved bytes, payload larger than the negotiated maximum, empty payload, undecodable JPEG, `seq` that goes backwards or repeats within one session (duplicate), and `timestamp_ns` that decreases.
  - Function: `parse_frame(bytes_msg) -> (seq, timestamp_ns, jpeg_bytes)`; its inverse `build_frame(...)` is used by the tests and by a Python mock client.
- [ ] Downlink = one WebSocket *text* message, JSON. Field names are **snake_case everywhere on the wire** (`timestamp_ns`, not `timestampNs`); the C# DTOs map them explicitly. Pose response:
  `{ "type": "pose", "schema": 1, "session_id": str, "seq": int, "timestamp_ns": int, "clock_id": str, "rvec": [r0,r1,r2], "tvec": [tx,ty,tz], "marker_ids": [int...], "rms_reproj_px": float, "registration_rms_mm": float|null, "latency_ms": float, "calibration_hash": str, "geometry_hash": str }`.
  - `tvec` in metres (camera frame, OpenCV convention); `rvec` is the OpenCV Rodrigues vector for the same model-to-camera pose.
  - `timestamp_ns` and `clock_id` are echoed from the uplink; they identify the *image*, not the moment the service finished.
  - `registration_rms_mm` is `null` if no full board solve happened on this frame.
- [ ] Explicit "no pose" response, so a client never waits for a timeout: `{ "type": "no_pose", "seq": int, "timestamp_ns": int, "reason": "no_markers" | "gate_rejected" | "stale" | "decode_error" | "queue_overflow" }`. Never send an identity or zero pose to mean "none".
- [ ] Sessions: the `hello` reply carries `session_id`; `seq` restarts per session; a reconnect starts a new session and the client resets its histories and anchors. Bind responses to the session they belong to.
- [ ] Bounded everything: maximum frame bytes, maximum queue depth (1-2, drop oldest), maximum message size on the socket, per-connection detector/filter state (no state shared between clients).
- [ ] Binding: default `127.0.0.1`. Listening on another interface requires an explicit option AND an authentication token in `hello`; the remote-Android case (service on the lab PC) is the reason for the option, not a reason for the default.
- [ ] Keep `IArucoPoseBridge` unchanged as the seam; WebSocket and JSON dependencies live only inside `WebSocketPoseBridge`.

### 1.3 Handshake (`python/handshake.py`)

- [ ] Parse incoming `hello`:
  ```json
  { "type": "hello", "client": "<id>", "version": "0.1", "frameWidth": 1280, "frameHeight": 720, "frameFormat": "jpeg-y8", "targetFps": 15 }
  ```
- [ ] Build `ready` reply containing the calibration profile keyed by `client`:
  ```json
  { "type": "ready",
    "calibration": { "fx":..., "fy":..., "cx":..., "cy":..., "k1":..., "k2":..., "p1":..., "p2":..., "k3":..., "imageWidth":..., "imageHeight":... },
    "boardConfig": { "dictionary": "DICT_4X4_50", "markers": [{"id":0,"position":[x,y,z],"normal":[nx,ny,nz],"roll_deg":0.0,"size_m":0.020}, ...] }
  }
  ```
  **[F08]** The board comes from the shared marker/geometry config (`python/config/markers/*.json` through `eyelab_paths`), not from a literal. Each marker carries its own `size_m` and its `roll_deg` (the in-plane rotation that fixes the corner order; omitting it silently rotates the marker model). There is **no default marker size**: the earlier 12 mm default is the wrong scale for the current prints (20 mm and larger) and, as a pure scale error, it would reproject perfectly while giving wrong depth. A missing `size_m` is a hard error. `ready` also carries `calibration_hash` and `geometry_hash` of exactly what the service loaded.
- [ ] Look up the calibration profile for `client` in the shared config tree (`python/config/cameras/`, via `eyelab_paths`), not in a private `calibrations/` folder. If missing, reply with `{"type":"error","reason":"calibration_missing","client":"<id>"}` and close — Unity will then offer to launch the calibration flow.

### 1.4 Service main loop (`python/eyelab_service.py`)

- [ ] Refactor `webcam_pipeline.py` so its core ArUco-detect-and-solve logic is a function `estimate_pose(jpeg_bytes, calib, board) → PoseResult`. Keep the existing webcam-from-VideoCapture variant working for the standalone CLI.
- [ ] Implement WebSocket server (default `ws://0.0.0.0:8765`). One client at a time; reject second connection with `{"type":"error","reason":"busy"}`.
- [ ] Per-connection state: `(client_id, calib, board, seq_counter, frame_queue depth=2)`.
- [ ] Worker task: pop newest frame from queue, run `estimate_pose`, send pose response. Drop oldest if queue full.
- [ ] Heartbeat: respond to WS pings; close on 15 s of no traffic.
- [ ] Logging: append JSONL to `python/.logs/service_<YYYYMMDD_HHMMSS>.jsonl` — `{ts_recv, ts_sent, latency_ms, seq, marker_count, rms_reproj_px}` per frame.
- [ ] CLI: `python eyelab_service.py --port 8765` (loopback by default, see 1.2). Calibration and geometry are resolved through `eyelab_paths` (`--config-dir` only to override the tree).
- [ ] **[F08]** Headless entry point: the processing core (`estimate_pose`) imports no tkinter and is reused by the GUI pipeline (`AGENTS.md`: no logic in `eyelab_gui.py`). Each connection owns its own `ArucoPipeline`-equivalent state (lock, Kalman, carryover); two sessions never share a filter.

### 1.5 Tests (`python/tests/test_handshake.py`)

- [ ] Unit-test `parse_frame` with the golden fixtures (valid, bad magic/version/reserved, oversize, empty, undecodable, duplicate and wrapping `seq`) **[F08]**. The same fixtures are loaded by a C# test so both endpoints agree.
- [ ] Unit-test handshake with fake `hello` strings (valid and invalid).
- [ ] Integration test: spin up service, connect a fake client, send a known-good frame (a JPEG containing a real ArUco marker captured from `webcam_pipeline.py`), assert pose returned.

**Done when:**
- `python eyelab_service.py` starts; you can `wscat -c ws://localhost:8765/aruco`, send a hello, and get a `ready`.
- An end-to-end test: connect, send 30 captured-from-disk JPEG frames, get 30 pose responses with `marker_ids` populated.

## Phase 2 — Unity bridge layer (~2–3 days)

**Goal:** the abstraction that lets us swap C → A → B without touching anything else.

### 2.1 `IArucoPoseBridge.cs`

```csharp
namespace EyeLab.Bridge
{
    public struct PoseResult
    {
        public ulong frameTimestampNs;
        public Vector3 tvec;            // OpenCV camera frame, metres
        public Vector3 rvec;            // Rodrigues vector
        public int[] markerIds;
        public float rmsReprojectionPx;
        public float registrationRmsMm; // -1 if not a full board solve
        public float latencyMs;
    }

    public interface IArucoPoseBridge
    {
        bool IsConnected { get; }
        Task ConnectAsync(BridgeConfig cfg, CancellationToken ct);
        Task<PoseResult?> EstimatePoseAsync(
            ReadOnlyMemory<byte> jpegYBytes,
            int width, int height,
            uint seq,
            ulong frameTimestampNs,
            CancellationToken ct);
        Task DisconnectAsync();
        event Action<CalibrationProfile> OnCalibrationReceived;
        event Action<string> OnConnectionLost;
    }
}
```

### 2.2 `BridgeConfig` (ScriptableObject)

- [ ] Fields: `kind` (enum: WebSocket | Mock | Native | OpenCVForUnity), `wsUrl` ("ws://localhost:8765/aruco"), `clientId` ("auto" → derive from device), `frameWidth`, `frameHeight`, `targetFps`, `connectTimeoutSeconds`, `frameTimeoutMs`.

### 2.3 `WebSocketPoseBridge.cs` (Phase 1's counterpart)

- [ ] Use NativeWebSocket. On `ConnectAsync`: open WS, send `hello` JSON, await `ready` (or `error`), raise `OnCalibrationReceived` with the parsed `CalibrationProfile`.
- [ ] On `EstimatePoseAsync`: pack the 20-byte header (see 1.2) + JPEG into a single byte[] of length 20+jpeg.Length; send as binary; await a text response (`pose` or `no_pose`) with matching `seq` and `session_id`. Resolve. Timeout after `frameTimeoutMs`. Ignore responses from an old session.
- [ ] Use `XREALMainThreadDispatcher.PerformActionInUpdate(...)` to marshal the result back to the Unity main thread before returning.
- [ ] Reconnect: exponential backoff 250 ms → cap 5 s. Re-handshake.

### 2.4 `MockPoseBridge.cs`

- [ ] Returns a canned pose every call after `frameTimeoutMs / 4` simulated delay. Useful for Editor smoke tests of the rendering pipeline without a camera.
- [ ] Configurable: known `tvec`, `rvec` so the wireframe lands at a predictable place in the scene.

**Done when:** Editor scene `00_Bringup.unity` containing a single `BridgeTester` MonoBehaviour can connect to a running Python service, send a hardcoded JPEG (a `Resources/test_marker.jpg`), and log the returned pose.

## Phase 3 — frame capture (~2–3 days)

**Goal:** unify Editor and Android camera sources behind one interface.

### 3.1 `IFrameSource.cs`

```csharp
public struct CameraFrame
{
    public ulong timestampNs;
    public int width;
    public int height;
    public ReadOnlyMemory<byte> grayscaleY; // Y plane / 8-bit grayscale
}

public interface IFrameSource
{
    bool IsRunning { get; }
    Task StartAsync();
    Task StopAsync();
    event Action<CameraFrame> OnFrameAvailable;  // raised on background thread
}
```

### 3.2 `WebCamFrameSource.cs` (Editor / Standalone)

- [ ] Use `UnityEngine.WebCamTexture`, default device, 1280×720.
- [ ] Each `LateUpdate`: if `webcam.didUpdateThisFrame`, copy pixels to a `Texture2D`, get `Color32[]`, convert to single-channel grayscale via `0.299R + 0.587G + 0.114B` (or just take G channel — cheaper, ~equivalent for ArUco).
- [ ] Raise `OnFrameAvailable` with a fresh `byte[]`.

### 3.3 `XREALEyeFrameSource.cs` (Android)

- [ ] Use `XREALRGBCameraTexture.CreateSingleton().StartCapture()`.
- [ ] Each frame: `var yuv = singleton.GetYUVFormatTextures(); var yTex = yuv[0];` — the Y plane is already 8-bit grayscale.
- [ ] Read it back to CPU using `AsyncGPUReadback.Request(yTex, ...)`. Take the callback's `NativeArray<byte>`, copy into a managed `byte[]`, raise `OnFrameAvailable`.
- [ ] Use `XREALPlugin.TryGetRGBCameraFrame(ref ulong)` to get the timestamp at the same Update tick.

### 3.4 JPEG encoding

- [ ] In a `FrameEncoder` static utility: `byte[] EncodeY8AsJpeg(byte[] gray, int w, int h, int quality=85)`.
- [ ] Use Unity's built-in encoder via a temporary `Texture2D` with `TextureFormat.R8`, `EncodeToJPG(quality)`. ## Phase 4 — geometry overlay rendering (~3 days)

**Goal:** display the .unv-derived wireframe at a fixed pose in the scene. No registration yet — just verify the renderer.

### 4.1 `WireframeData.cs`

- [ ] **[F08]** Generate the DTOs from, and test them against, fixtures produced by the real Python parser (`UNVParser.parse()` output), not from this sketch. The parser's actual shape is `{ metadata, nodes, traceLines, coordinateSystems, units }` where `units` is an **object** (`code`, `name`, `description`, `lengthFactor`, `forceFactor`, `temperatureFactor`), nodes carry `exportCS` and `displacementCS`, and coordinate systems carry `id`, `type` ("rectangular" | "cylindrical" | "spherical" | "unknown"), `origin`, `xAxis`, `yAxis`, `zAxis`:
  ```csharp
  [Serializable] public class WireframeData {
      public Metadata metadata;
      public Node[] nodes;
      public int[][] traceLines;           // edge pairs after pen-up splitting
      public CoordinateSystem[] coordinateSystems;
      public Units units;                  // object, not a string
  }
  [Serializable] public class Units { public int code; public string name; public double lengthFactor; /* ... */ }
  [Serializable] public class Node { public int id; public double x, y, z; public int exportCS, displacementCS; }
  [Serializable] public class CoordinateSystem { public int id; public string type; public double[] origin, xAxis, yAxis, zAxis; }
  ```
  Coordinates and CS origins arrive in **metres** (the parser converts them). Do not mutate coordinates in place or convert twice; apply the basis change (Conventions) to the whole geometry once, at load. Only rectangular systems are produced; the parser rejects the rest.

## Phase 5 — pose application & structure anchor (~3–4 days)

**Goal:** place the wireframe at the correct world-frame pose using ArUco poses from the bridge.

**Approach (locked 2026-05-09):** introduce an `IStructureAnchor` interface; v0 implementation is `EwmaStructureAnchor` (option iii from the grill — plain GameObject Transform + EWMA smoothing + outlier rejection). The interface is deliberate: option (i) `ArFoundationStructureAnchor` (uses `XRAnchor` for SLAM-corrected stability) is the planned upgrade if long-session drift is measured to matter. See CONTEXT.md "Resolved decisions" §3.

### 5.1 `HeadPoseHistory.cs` **[F05]**

- [ ] Ring buffer `(long hostTimeNs, int trackingEpoch, Pose T_world_from_head)` with capacity covering at least 1 s at the sampling rate. Samples are stamped with the clock that produced them (Unity/host); record which clock in the type, not in a comment.
- [ ] Each `Update`: append the head pose with its host time and the current `trackingEpoch` (incremented on every tracking-origin change, relocalisation or session restart).
- [ ] `bool TryLookup(long hostTimeNs, out Pose T_world_from_head)` — **interpolate between the two samples that bracket the requested time** (position `Vector3.Lerp`, orientation `Quaternion.Slerp`). Return `false` — never a nearest or oldest entry — when the time is not bracketed (older than the buffer, newer than the newest sample, or the bracketing samples belong to different `trackingEpoch`s). A caller that gets `false` drops that pose.
- [ ] **Clock mapping.** Camera-frame timestamps from the SDK are converted to the head-pose clock by an explicit `ClockMap` (offset estimated from paired samples, with its measured jitter). Until the offset is measured on real hardware, `ClockMap` is a stub that fails closed (no composition) rather than assuming the clocks agree.
- [ ] Bind the timestamp to the acquired image: the `(frame handle, SDK timestamp)` pair is captured together at acquisition and travels with the frame to the bridge and back; never re-read a "current" timestamp later.
- [ ] On session or tracking-origin change: clear the history, the anchor (5.3) and any pending bridge requests.

### 5.2 `CoordinateConverter.cs`

- [ ] One static class. Single conversion routine (THEORY.md §6.3):
  - `Pose OpenCvToUnity(Vector3 rvecOpenCv, Vector3 tvecOpenCv)`:
    - Build OpenCV → Unity flip via `F = diag(1, -1, 1)`.
    - Convert Rodrigues to a rotation matrix, conjugate by F, extract Quaternion.
    - Negate `tvec.y`.
  - Document the formula in comments. Never duplicate this conversion anywhere else.

### 5.3 `IStructureAnchor.cs` and `EwmaStructureAnchor.cs`

```csharp
public interface IStructureAnchor {
    Pose CurrentPose { get; }                     // T_world_from_structure
    Transform AnchorTransform { get; }            // wireframe parents to this
    void OnPoseEstimated(in PoseResult pose);     // called by bridge subscription
    bool IsLocked { get; }                        // true after first stable pose
    event Action OnLocked;
}
```

- [ ] `EwmaStructureAnchor` (the v0 default; chosen 2026-05-09):
  - Hold a `Pose currentAnchor` (`T_world_from_structure`).
  - EWMA smoothing: `α = 0.4` for the first ~10 frames after locking, then `α = 0.15`. Position is straight EWMA; rotation is `Quaternion.Slerp(prev, new, α)`.
  - Outlier rejection: maintain a running stddev of position deltas; reject any new anchor whose delta exceeds `3 × stddev` (with `stddev` floored at 5 mm to handle warmup).
  - On each pose from the bridge:
    1. `ClockMap` converts `pose.frameTimestampNs` to the head-pose clock; `HeadPoseHistory.TryLookup` returns `T_world_from_head(t_capture)` or the pose is dropped (stale or uncovered time).
    2. `T_camera_from_structure = CoordinateConverter.OpenCvToUnity(pose.rvec, pose.tvec)` — the **raw** per-frame camera pose (not the service's Kalman output, which lags and would be treated as instantaneous).
    3. `T_world_from_structure(t_capture) = T_world_from_head(t_capture) * T_head_from_camera * T_camera_from_structure(t_capture)`. `T_head_from_camera` is the camera extrinsic; in v0 it is the identity **as a placeholder**, so v0 results carry an unquantified bias, and Phase 8 replaces it only with a procedure that is actually validated. Do not describe the v0 composition as accurate.
    4. Apply outlier rejection to the composed world pose; EWMA-update `currentAnchor` (the stationary world anchor is filtered *after* composition, so head motion during the filter lag does not move the anchor); update `AnchorTransform`.
  - Expose `AnchorTransform` as a Transform that the wireframe is parented to.

- [ ] **Future / backup:** `ArFoundationStructureAnchor` — same interface, uses `ARAnchorManager.AddAnchor(...)`. Deferred; tracked in CONTEXT.md "Resolved decisions" §3.

### 5.4 Wire up

- [ ] In `20_EMA.unity`: a single GameObject holds `BridgeRunner` + `FrameSourceRunner` + `HeadPoseHistory` + `StructureAnchor` + the GeometryRenderer.
- [ ] On Awake: connect the bridge, await `OnCalibrationReceived` (the calibration is informational here — only the service uses it), start the frame source.

**Done when:** in Editor with a webcam pointed at a printed ArUco board, the wireframe lands stably on the marker. Move the camera, the wireframe sticks to the marker.

## Phase 8 — head-camera extrinsic, then per-eye display calibration (week 3+, effort to be re-estimated) **[F13]**

**Why this phase was rewritten.** The earlier version fitted one rigid head-camera offset from four visual alignments at one working distance and called that SPAAM. That is not SPAAM, and it does not establish where the *wearer's eye* is relative to the display, which is what decides whether an optical see-through overlay lands on the specimen. Video see-through and optical see-through are different products with different gates:

- **Video overlay** (diagnostic only here): draw on the captured image and show that image. Correct image registration needs no world tracking and no eye model.
- **Optical see-through** (the actual requirement): needs the camera/head/eye/display chain, tracking, and compensation to *presentation* time. A factory camera-to-head transform does not by itself give the wearer's eye position or a correct display projection (cf. Gilson et al., PMC3142613).

### 8.1 Head-camera extrinsic `T_head_from_camera`

- [ ] Obtain it from a source whose provenance is known (SDK-exposed factory extrinsic, once verified to exist and be applicable to this firmware/mode) or measure it with a rigid-motion procedure against a tracked reference; record the method, the data and the residual. Four casual visual alignments are not a measurement.
- [ ] Store with the camera profile it belongs to; never mix extrinsics across image modes.

### 8.2 Per-eye display projection

- [ ] Specify the procedure before writing `SpaamFlow.cs`: number of correspondences per eye (a full 3x4 projection needs well more than four, spread over depth), how the wearer's fit is captured, how repeatability is checked, and how the result is validated. Only a procedure with those parts may be called SPAAM.
- [ ] Per-user and per-eye: results are stored per user and per eye and invalidated when the glasses are re-seated (fit changes).

**Gates (independent of each other).** Video-overlay alignment: reprojection of known points into the displayed image. Optical alignment: error measured at **held-out** positions and depths, for each eye, under motion, after repeated fitting — reported with the agreed statistic, not by visual agreement near one distance.
