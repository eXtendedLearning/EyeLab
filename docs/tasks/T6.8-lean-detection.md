# T6.8 — Lean region detection on the Beam Pro

> Written 2026-11-22, built as 0.4.010 (plugin ABI 4). Run 1 (2026-11-22): late frames now sit at the idle-worker
> floor (3-7 %), so detection is no longer what loses the margin; plate L tilted gives non-planar poses with no wrong
> trusted pose; the remaining parity differences are sub-pixel refinement flips, not the crop. Next: B3b. Parent: T6.7 run 1
> (`docs/tasks/T6.7-detection-budget.md`). One run of about 2 min plus a bench of a few seconds. Needs the 25 mm ChArUco
> board (5×7, 19 mm markers, ids 0-16) and plate L (markers 40-43, 20 mm). Plate A and the cube are not used.

## Why

T6.7 run 1 found that only the region at 1 thread comes near the render margin: 5-7 % late Unity frames at 27-29 poses/s,
against 12-18 % with full frames. That is still above the ≤ 4 % target. Three things in that run were also fixable:

- **The region cost more than its area suggests** (25-35 ms for 16 % of the frame). ArUco's perimeter limits shrink with the
  crop. Scaled back, detection was 30 % cheaper offline with the same markers found.
- **The region did not match Python exactly** on 3 of 23 bench frames, all with sizes that were not multiples of 8.
- **Plate L's non-planar solves could diverge** (RMS up to 2198 px) and were trusted. Standing on the table, its upward face
  was edge-on, so most poses came from one face only.

Plate A at 75 cm is too small for a stable normal and is dropped. The board gave 1 % wrong poses and 2.8 mm high-pass.

  - bench region exact against Python on the same crop (within 0.01 px on every frame).

## Run 1 (2026-11-22, 0.4.010, plugin ABI 4)

Run `20261122_153358_lean`, analysed with `python -m xreal_gates bp` (0.4.011 report: still metrics skip each step's
first second and take the normal in the room; parity counts refinement flips). Eye frames 3549, processed 1810, skipped
while busy 1139. Placing plate L took longer than `l_ready`: it came into view about 8 s into `l_roi_still`, so that step
is mostly placement, and the plate L comparison uses `l_r15_still`.

### Cost

| | T6.7 run 1 | T6.8 run 1 |
|---|---|---|
| bench region, 1 thread, real Eye frames | 29.4 ms | 21.2 ms (−28 %) |
| bench region, all frames | 17.7 ms | 16.3 ms |
| live region on the board, still | 25.6 ms | 24.9 ms |
| live region on plate L, still (`l_r15_still`) | 33.1 ms (standing) | 50.3 ms (tilted, 23 % of the frame) |

- **The bench got cheaper, the live board did not move.** The board's region is 17 % of the frame either way.
- **Capped steps cost more per frame:** 42.7 ms against 24.9 ms on the same board region. Most likely the cores clock
  down between frames at an 11 Hz duty; not checked.
- **The 15 Hz cap gives 11 Hz.** It skips a frame when less than 1/15 s has passed since the last start, so two Eye
  frames 66.6 ms apart are one too few and every third frame runs. A tolerance fixes it, if the cap is kept.

### Render margin

| step | mode | poses/s | late Unity frames | late when the worker is idle |
|---|---|---|---|---|
| b_roi_still | region | 27.6 | 4.7 % | 5.3 % |
| b_r15_still | region, cap | 10.9 | 5.1 % | 5.7 % |
| l_r15_still | region, cap | 11.0 | 4.3 % | 3.0 % |
| b_ready, b_roi_move | region | 17-20 | 6.7-8.6 % | 4.1-7.6 % |

- **Late frames on still steps no longer follow the worker.** On the board they are as frequent with the worker idle as
  busy (4.0-6.2 % against 5.3-7.6 %).
- **The floor without detection is now 3-7 %,** against 2.8 % in T6.6 run 2. So ≤ 4 % is not reachable by cheaper
  detection alone. A step with detection off in the same session is needed to measure the floor; it goes in B3b.

### Pose quality (still steps, first second skipped, normal in the room)

| target | step | poses | non-planar | wrong, all | trusted | wrong among trusted | high-pass |
|---|---|---|---|---|---|---|---|
| board, 510 mm | b_roi_still | 292 | — | 3 | 6 | 0 | 3.8 mm all poses |
| board | b_r15_still | 118 | — | 0 | 2 | 0 | 1.4 mm all poses |
| plate L tilted, 618 mm | l_r15_still | 119 | 116 of 130 | 1 | 112 | 0 | 4.6 mm trusted |

- **The board's 14 wrong trusted poses (report before 0.4.011) all fell in the first 0.4 s of `b_roi_still`,** while the
  head was still settling (head position std 57 mm in that step, 3 mm in `b_r15_still`). Counted in camera coordinates,
  a head turn also reads as a wrong normal. From 0.4.011 the report skips each step's first second and carries the normal
  into the room with the head pose at `cam_ts`.
- **The board is right but rarely trusted.** Near-frontal at 51 cm, IPPE's two solutions are about 15° apart with a ratio
  of 1.6, so the ratio rule trusts 2 % of the poses while only 1 % are wrong. For the board, the rule needs to depend on
  how many markers the pose uses: with all 17 markers, `b_r15_still` had 0 wrong in 110.
- **Plate L tilted 45° works.** 89 % of its still poses use both faces, 94 % are trusted, none of the trusted ones is
  wrong, with a 4.6 mm trusted high-pass. Its remaining wrong poses are planar poses from one to three markers.

### Parity

- **Bench full frames:** exact (0.0009 px, 0.001 mm).
- **Bench region:** 22/23 exact; the one difference (0.74 px) is a refinement flip.
- **Live:** ids equal on 112/112 region frames and 68/69 full frames. Of the 92 differing region corners, 74 are
  refinement flips; all 3 differing full-frame corners are.

**What a refinement flip is.** ArUco's sub-pixel refinement keeps a corner on one side and rejects it on the other:
one side has the unrefined corner, which is why the differences stay under 1 px. It happens on full frames as well, and
with regions that are multiples of 8, so the T6.7 hypothesis (CLAHE over fractional tiles) is refuted. Both sides run
OpenCV 4.13.0 with the same parameters, so the likely cause is floating point (NEON against x86) near the accept
threshold. It cannot be made exact. The report now counts the flips, and parity means exact apart from them.
